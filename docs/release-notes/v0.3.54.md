# Jiva v0.3.54 — Session Restore Fix, Container Persona Support & Documentation Restructure

## Bug Fixes

### Conversations saved under the session ID (HTTP server)
`SessionManager` now passes the session ID to `ConversationManager` as a default conversation ID, so
conversations are stored under the same ID that is used to restore the session.

Two edge cases are handled in `ConversationManager`:
- **Restored sessions keep their metadata.** The first save after a restore loads the existing
  conversation, so its title, `created` timestamp and cumulative token totals are no longer reset.
- **Resetting a conversation starts a new one.** `setCurrentConversationId(null)` also clears the
  default ID, so `resetConversation()` no longer overwrites the previous conversation with the
  session ID.

## Deployment

- `Dockerfile` copies `scripts/` into the builder stage (required by the build) and ships
  `examples/personas` to `/app/.jiva/personas` so sub-agent spawning has personas available.
- `.dockerignore` / `.gcloudignore` no longer exclude `examples/` (personas are needed at runtime).
